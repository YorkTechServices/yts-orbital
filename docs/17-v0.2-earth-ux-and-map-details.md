## User-facing changes

City pins, the selected-location ring, and the satellite marker now use camera distance, field of view, and viewport height to hold a bounded apparent size. Forty-one curated metropolitan references provide broader global coverage. Important megacity labels remain available at broad views; other city labels and markers fade in at regional distances. The selected-location symbol is a thin 18-pixel target with a restrained pulse and no stem. The satellite retains a larger invisible interaction sphere plus an accessible 44-pixel screen-space target; clicking it from Earth or Location view activates Satellite follow mode without selecting the Earth behind it.

Touch devices use a lower OrbitControls rotation speed, stronger damping, and slower zoom than pointer-accurate desktop devices. Click selection retains an eight-pixel movement threshold, so drags and swipes are not treated as taps. `touch-action: none` and overscroll containment apply only to the globe canvas.

The mobile information tabs follow an explicit `SelectedEntity` union: none, location, or satellite. A new location activates the Location context and brings the `GEOSPATIAL VISUALIZATION / EARTH FIXED` header into view on screens up to 820 pixels wide. The full location card is shown there directly above the globe rather than duplicated in the lower `GEOSPATIAL SURFACE` controls. Location name, country/region, coordinates, and sourced population are ordered first. Missing geographic values are omitted rather than replaced with invented values. A persistent label remains anchored to the selected surface point while the camera moves.

## Map Details controls

Earth Explorer exposes three keyboard- and touch-accessible pressed-state controls:

- Country boundaries
- States / provinces
- City labels

Country boundaries, state/province boundaries, and city labels are on by default. Country data loads for the initial global view, while state/province data remains deferred until the camera enters the layer's regional distance. Boundary opacity fades near the maximum useful distance, and each control can still be switched off independently.

## Layer architecture

`lib/layers/map-layers.ts` owns the stable layer definitions and runtime state. Each definition includes an ID, display name, category, planetary body, default/current visibility, useful camera-distance range, source and attribution, load/error state, lazy-load flag, and optional legend metadata.

`components/globe/map-details-layer.tsx` owns boundary loading and rendering. Data modules and rendering are separate: each generated asset is a compact array of geographic line coordinates. The renderer converts each adjacent coordinate pair to the existing Earth-fixed scene frame and combines an entire tier into one `BufferGeometry` and one material. Turning a boundary layer off releases that geometry. Dynamic imports remain cached by the browser for later use.

This contract can later accept QGIS-exported line data, remote versioned assets, tiles, or another planetary body without changing satellite propagation.

## Data source and preparation

The boundary source is [Natural Earth](https://www.naturalearthdata.com/) vector release 5.1.2 at 1:110m scale:

- `ne_110m_admin_0_boundary_lines_land.geojson`
- `ne_110m_admin_1_states_provinces_lines.geojson`

Natural Earth data is in the public domain. Source files are downloaded from the tagged `nvkelso/natural-earth-vector` repository only during preparation; the application does not hotlink them at runtime.

Run:

```bash
npm run prepare:map-details
```

The script keeps line geometry, rounds coordinates to 0.01 degrees, removes adjacent duplicate points, splits lines where adjacent longitudes cross the antimeridian, densifies remaining spans to at most 2 degrees so they follow the globe surface, and writes versioned metadata with the compact assets under `data/map-details/`. The generated Admin 0 and Admin 1 files are approximately 44 KB and 14 KB respectively in v0.2.

## Performance and cleanup

- Boundary JSON is split from the initial application bundle through static dynamic imports.
- Admin 1 parsing and geometry creation wait for regional camera distance.
- Camera-distance checks mutate material opacity in the render loop; React state changes only when a layer crosses its useful-distance threshold.
- Each boundary tier uses one geometry and material rather than one React component per line.
- Generated geometries are disposed when disabled, replaced, or unmounted.
- Existing city markers reuse memoized positions and update refs rather than React state each frame.

## Known limitations

- Natural Earth 1:110m is intentionally generalized and is not suitable for local legal-boundary work.
- Admin 1 coverage follows the Natural Earth release and is not uniform across all countries.
- City labels use importance, distance, and horizon gating rather than a full screen-space collision engine.
- Layer visibility is session state and is not persisted between browser visits.
- WebGL line width support varies by platform, so hierarchy relies primarily on color and opacity.
