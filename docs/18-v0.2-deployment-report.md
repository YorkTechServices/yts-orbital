## Release Summary

Version 0.2 expands Earth Explorer into a more complete geospatial interface. The release adds geographic boundaries, broader city coverage, persistent location context, direct satellite interaction, improved mobile controls, and a startup progress display that accurately communicates catalog-loading delays.

## Implemented Features

### Map Details

- Added country boundaries using a prepared Natural Earth Admin 0 dataset.
- Added state and province boundaries using a prepared Natural Earth Admin 1 dataset.
- Enabled country and state/province controls by default.
- Kept state/province geometry distance-gated so detailed data loads only at useful regional ranges.
- Added a centralized typed layer registry for visibility, loading, errors, and distance rules.
- Added lazy asset loading and geometry cleanup when layers are disabled or unmounted.
- Added a reproducible map-data preparation script with coordinate rounding, antimeridian splitting, and segment densification.

### Cities and Location Selection

- Expanded the curated city dataset to 41 major metropolitan references.
- Increased useful city-label coverage across global and regional views.
- Added more globally important labels across the Americas, Europe, Africa, Asia, and Oceania.
- Added camera-aware marker and label sizing to prevent excessive growth while zooming.
- Reduced the selected-location ring to a smaller geographic marker.
- Added a persistent label anchored to the selected point on Earth.
- Moved complete selected-location information above the globe.
- Removed duplicate location details from the lower mobile information panel.
- Added automatic mobile scrolling so newly selected location details remain visible.
- Continued omitting unavailable geographic fields rather than fabricating values.

### Satellite Interaction

- Made the displayed satellite selectable directly from Earth and Location views.
- Satellite selection now switches the dashboard into Satellite mode.
- Added a 44 by 44 CSS-pixel accessible satellite interaction target.
- Added mouse, touch, and keyboard activation behavior.
- Prevented satellite clicks from propagating through to the Earth selection surface.
- Reduced satellite marker glow and removed the point light that caused excessive Earth illumination.

### Mobile and Globe Controls

- Reduced touch rotation sensitivity and increased damping.
- Added an eight-pixel click-versus-drag threshold to prevent accidental geographic selections.
- Limited `touch-action: none` to the globe canvas.
- Verified responsive selected-location layouts at 375, 390, and 430-pixel viewport widths.

### Startup Experience

- Added an always-visible progress bar throughout the pre-application startup sequence.
- Progress begins at 0 percent and remains visible until entry is available.
- Progress reaches 100 percent only when the catalog is ready and the startup sequence is complete.
- Slow catalog requests hold at 94 percent instead of falsely reporting completion.
- Added `WAITING FOR ORBITAL CATALOG` status during delayed catalog responses.
- Added accessible progress semantics, including current value and descriptive status text.

## Security Hardening

A focused public-facing application review was completed before release.

- Added baseline response headers:
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: DENY`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - A restrictive permissions policy for camera, microphone, and geolocation
- Added strict shape and range validation before restoring observer coordinates from browser storage.
- Limited reverse-geocode location hints to 120 characters.
- Confirmed external API requests use fixed trusted endpoints, encoded query parameters, input bounds, and request timeouts.
- Confirmed React text rendering prevents the reviewed geographic data from becoming an HTML injection path.
- Confirmed no exposed secrets, dynamic evaluation, or unsafe HTML rendering patterns were present.
- Production dependency audit reported zero known vulnerabilities.
- No release-blocking security findings were identified.

### Remaining Recommendation

Apply request rate limiting to public API routes at the hosting or edge layer. Infrastructure-level enforcement is preferred because in-process limits are unreliable across serverless instances.
